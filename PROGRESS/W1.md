### 2026-07-06(周一)@ 公司 Windows(晚间 code review + 重构)

**背景**:pull 时把 journal 错误合到 main → 本地 `git reset --hard origin/main` 救回;学习了 fetch/pull/reset/revert/cherry-pick/rebase 完整心智模型

**AI code review 发现**
- Decoder Bug 1:`decodeSimpleString` 在 Array 内被调用时半包不返回信号,导致状态错乱
- Decoder Bug 2:非 -1 的负数长度或非数字长度会抛 IllegalArgumentException / NumberFormatException,而不是明确的协议异常
- Array 只识别 `$` 和 `+`,不支持嵌套 Array,遇到未知类型静默吞掉
- `RespSimpleString` 用 `@Data` + final 字段语义混乱(setter 生成不了 + 无参构造缺失)
- `RespArray` 元素类型是 `List<Object>`,失去编译期类型安全

**重构改动**
- 新增 `RespObject` sealed interface(permits 3 impl),统一顶层类型
- 新增 `RespProtocolException`,协议违规明确抛出
- `RespSimpleString` / `RespBulkString` / `RespArray` 全部 implement RespObject,`@Data` 换成 `@Getter @AllArgsConstructor @EqualsAndHashCode @ToString`
- `RespArray.elements` 从 `List<Object>` 改为 `List<RespObject>`
- `RespDecoder` 引入 `decodeOne` 统一分派,switch expression + 抛异常处理未知类型;顶层单次 mark/reset;Array 通过 `decodeOne` 递归天然支持嵌套
- `RespEncoder` 完整实现,支持 nested Array;用 `instanceof x` pattern matching(Java 16+)
- 4 个新测试:粘包 / Array 半包 / SimpleString 在 Array 内半包(回归 Bug 1)/ 非法长度和未知类型抛异常

**学到的 Java 新特性**
- `sealed interface` + `permits`(Java 17):编译期锁死继承,配合 switch 可穷举检查
- `case ->` switch expression(Java 14):无 break,可当表达式返回值
- `instanceof x` pattern matching(Java 16):一句话搞定类型检查 + 变量绑定
- **Netty 异常包装机制**:decoder 里抛的异常被包装成 `DecoderException`,测试用 `hasRootCauseInstanceOf` 断言根因
